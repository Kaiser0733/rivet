## Open checks resolved

1. **Theme roles and alpha.** The old `RivetChatBackground` filled `surface`, so setting the new raised surface alone would put the wrong color on chat. It now fills `background`. Settings and History structural dividers use `outlineVariant` directly. `RivetOutlinedButton` uses `outline` at full opacity when enabled and retains a lower disabled opacity. History keeps the selected pin in primary and uses Material disabled icon content colors. The existing type roles and 8/12/16/20/28 dp shapes already match the plan. The replay sheet used to fetch the dark theme colors directly, so its old six colors are explicit at the existing replay call site. The source contrast check covers both themes, all six neutral backgrounds, both ink roles, enabled outlines, ink on filled signal and the error-container pairs. Light signal on the existing light error container is 4.01:1. This is below 4.5:1 for small text using the default action color, and the pre-batch pair was also below that threshold. Rendered focus, disabled and overlay combinations still need inspection.
2. **Copy ownership.** C1 was inline and C2 was absent. Both now have dedicated resources. C3–C9 were inline in `ChatScreen.kt`. C6's actual old line was “Rivet can inspect this project and will ask before changing files.” C15 belongs to the `active == null` branch in Settings, rather than `ProviderEditor.kt` or the generic provider strings. C16 changes only the prefix of the RAM-dependent estimate in `DeviceCard`. It preserves “about”, `formatParams(ceiling.maxParamsB)` and the context/1024 value in K. C19 belongs to `StarterGallery.kt`, rather than `StarterGalleryContent.kt`, which retains ordering, size formatting and the no-key footnote. The old C15 and C19 literals included final periods.
3. **Tools dismissal and focus.** `RivetApp` owns `processesOpen` and keeps the chat composed under `RightSlidePanel`. Close, Back and the existing scrim handler flip that flag. Tools' terminal entry still opens the terminal and closes the panel. The glyph is the same `ic_close` used by Settings. Actual TalkBack focus return needs a phone.
4. **C10 fixture.** `ErrorRow` consumes `ChatUiState.error`. The traced sources in `ChatViewModel` include user-facing errors for run stops and `ProviderError` text after `providerMessageText`. I found no real fixture reproducing the exact `error: {code} — {reason}` envelope at this boundary. C10 is omitted. The existing sanitizer, diagnostic, dismiss and conditional retry stay intact.
5. **Composer eligibility and clipboard.** `InputBar` shows its composer + through an `IconButton` enabled when ready and idle. Its sheet reads availability through clipboard MIME metadata and reads `primaryClip` on the row tap. Its text draft and applied-share IDs are saved per session. The Tools screenshot and the revoked-folder home screenshot show different states. Neither overrides the current code. The plus in the chat header has a different action.
6. **Inbound URI and MIME contract.** `MainActivity.consumeSharedContent(Intent?)` reads SEND/VIEW URIs and resolves the provider MIME if the intent omits it, calls `SharedContent.classify(action, mimeType, text, uri)` in `chat/ShareIntake.kt` and clears the consumed intent fields for replay protection. The classifier recognizes image MIME, zip and generic files. `ChatViewModel.receiveSharedContent(content: SharedContent)` passes files to `SharedFileCopy.copy`, which uses the transient readable `content:` URI with a 64 MiB limit. The view model emits an existing notice for failed reads. Zip routes to install review. Non-image files stage inbox paths and may include up to 8 KiB of text in the draft.
7. **Occupied session and picker gate.** After staging, `receiveSharedContent` waits for an idle and ready chat. Only an empty conversation with no pending share can land in place under the normal session store. For a conversation with messages, or one with a pending share, it calls `changeSession { store.create(...) }` before `land()`. `putSharedDraft` keys the staged photo or file text to that newly selected session. `InputBar` merges the share text into that session's saved draft once. `send` consumes the image associated with that session on explicit submit. There is no callable variant taking a target session or preserving an occupied current session. The code already avoids auto-send, but fails the no-switch condition for both picker types. Cancellation/recreation and picker compatibility could only be tested for an enabled picker, so no picker rows ship. An independent import path or an intake/session behavior change would cross the brief's scope.
8. **Checkpoint shape.** `RunCheckpointInfo.gitRef` is nullable and has no separate kind string or third variant. `RunCheckpointStore.begin` constructs a Git checkpoint when it has a ref and otherwise keeps the file copies, including if the Git checkpoint attempt fails. `RunCheckpointGate.startRun` builds “Before:” with a title truncated to 120 characters and the store caps all summaries at 200. The UI shows the full stored string and cannot recover the truncated source or infer a diff. There is no unfamiliar kind a fixture can supply to this schema.
9. **Live status and preview.** `chat/LiveStatus.kt` returns “Thinking” when neither tool execution, writing nor approvals win. That fallback includes getting ready and other non-provider work. It does not establish verbatim request dispatch. The existing public preview is produced through `thinkingPreview` and `displaySafeText` inside `ReasoningRow`. C14 applies only inside the active streamed reasoning branch when that visible preview is empty, the timer has the generic label and the view model says “Working on it…”. The broader timer fallback retains “Thinking”. `ChatProcessGroups.kt` already projects precise activity and keeps its wording and grouping.
10. **Worker selection.** `ChatScreen` owns the selected worker ID and obtains the ordered list via `workerSheetRows`. The 560 dp sheet in `WorkerSheet.kt` owns the actual selectable `AssistChip` nodes above the scrolling transcript. Only the matching ID sets `SemanticsProperties.Selected`. The `SubagentChip` menu opens the sheet and has no selected job state of its own. Stop, Continue and transcript filtering use their original callbacks.
11. **Turn identity and outcome.** A stopped attempt can clear streaming before the project journal catches up. Conversely, `ChatViewModel.finish` can set `RunPhase.Done` for an empty response before publishing the UI error. The reveal therefore requires the same observed turn ordinal, session composition, accepted-message counter and monotonic turn start, a newly published duration, a cleared live wall clock, a visible answer and a clean fold result. It is armed only for a latest live row that is still composed, never from a historical duration or a terminal flag alone. Explicit stop text, failed and interrupted flags, and the existing paused recovery state remain static. Historical rows with no verified completed outcome use the existing “Tools” label instead of inferring success. Legacy histories do not always carry per-turn terminal metadata. The existing interruption banner and error row continue to show their original reasons.
12. **Motion and touch bounds.** `FoldReveal` and its chevron use the Compose `MotionDurationScale` in the coroutine context. At zero the visible values are derived directly in composition. Otherwise the existing frame-clock animation accumulates scaled elapsed time. `RightSlidePanel` retains its stock Compose 220/160 ms behavior. The turn's 14 dp chevron is inside the clickable row, whose minimum height is 33 dp or 44 dp with replay export. Browser window close uses an `IconButton` sized 26 dp with a 14 dp glyph in `BrowserScreen.kt`. These are source dimensions. Effective touch bounds, overlap and TalkBack targets need device evidence, so the batch leaves their geometry alone.
13. **Specialist states.** `PhoneCaptureCoordinator` asks for consent and `PhoneCaptureService` then posts the named “Capture now” action. C18 therefore matches the actual path. The model estimate is only drawn when RAM is known. “Creating your replay…” is assigned when export starts. Existing no-story, encoder, distribution and other failures keep their specific feedback. The browser empty copy only changes where the URL is blank and no window is visible. The provider connection editor and phone setup instructions remain as they were.
14. **Test seams.** The repository has a pure turn segmentation seam, live status, clipboard, share classifier, worker list and chip policies, starter content, plus Robolectric tests for fold motion and browser UI. The new source checks pin literal ownership, palette and callback wiring where composed UI could not be run locally. The test results below distinguish those checks from actual Kotlin execution and from tests still owed on Android.
